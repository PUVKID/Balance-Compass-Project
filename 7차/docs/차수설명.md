## LEVEL 1 - Beginner

### 숫자가 있다고 바로 믿지 않기

인구가 -1명, 역 개수가 0.5개여도 컴퓨터는 숫자로 읽을 수 있다. 이번에는 그런 자료를 학습 입력에 넣기 전에 멈추게 했다. 예측 파일의 같은 열 이름 두 개나 중간 빈 줄도 놓치지 않도록 고쳤다.

사전 검사는 시험을 시작하기 전 준비물 검사와 같다. 정상 결과가 나와도 실제 위치가 맞는지, 과거에 그 정보가 있었는지, 논문 가설이 맞는지는 별도로 확인해야 한다.

## LEVEL 2 - Explorer

### 파일·관측·판정의 경계

원문 CSV 구조 → ID와 수치 → 특징 관측의 기간/원천 → 같은 조건의 서울 비교 → 가설 효과·구간 → 화면 근거 검사로 연결된다. 파일 행 수, 특징 관측 수, 계약 수와 단지 군집 수는 서로 다른 분모다.

## LEVEL 3 - Practitioner

### 사전 검사 실행과 실패 해석

Python3.12와 고정 requirements.txt/requirements_acquire.txt 환경에서 python -B -X utf8 -m rentlab.feature_preflight --features features.json --output new_preflight.json을 실행한다. 기존 파일은 덮어쓰지 않고 sklearn/engine을 불러오거나 학습하지 않는다.

## LEVEL 4 - Advanced

### 공통 계약과 영향 범위

input_contracts의 strict_csv는 논리 행 구조를 먼저 확인한 뒤 동일 바이트를 읽는다. 원행 리스트 전체를 복제하지 않고 ID 앞자리0을 보존한다. feature_store는 manifest와 join 양쪽에서 validate_observations를 공유하고, experiment_runner와 research_metrics는 holdout 고정 설정 검증을 공유한다.

research_protocol은 기존 고정 과학 조건을 판정하며 변경 설정을 기술 partial로 남긴다. run_dashboard는 measured 표시 전에 config·요청/유효 bootstrap·군집 근거를 확인한다. feature_preflight는 검사 보고서만 저장하고 모델 실행 모듈과 분리했다.

## LEVEL 5 - Expert

### 논문 해석과 재현 조건

H1–H8와15가족, 예측 alpha=.1/가설 family confidence=.95, seed20261126 및 최소 군집/지역 조건을 보존한다. B≥9999, ceil(.8B)≤B_valid≤B, k≥20은 확정 상태의 필수 근거다. 설정이 달라지면 효과가 있어도 기술 partial/inconclusive다.

H5는 같은 스냅숏·전체 서울 계약과 고정 라이브러리/추정기 인자를 비교한다. 선택된 모델·학습 반복수는 결과라 달라질 수 있다. CI가 estimate를 포함한다는 조건은 넣지 않았고 군집 percentile 근사의 한계를 유지한다. 새 유의성·가설·모델 성능을 주장하지 않는다.
