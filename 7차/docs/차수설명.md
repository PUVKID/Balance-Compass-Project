## LEVEL 1 - Beginner

### 숫자가 있다고 바로 믿지 않기

인구가 -1명, 역 개수가 0.5개여도 컴퓨터는 숫자로 읽을 수 있다. 이번에는 그런 자료를 학습 입력에 넣기 전에 멈추게 했다. 예측 파일의 같은 열 이름 두 개나 중간 빈 줄도 놓치지 않도록 고쳤다.

사전 검사는 시험을 시작하기 전 준비물 검사와 같다. 정상 결과가 나와도 실제 위치가 맞는지, 과거에 그 정보가 있었는지, 논문 가설이 맞는지는 별도로 확인해야 한다.

| 먼저 볼 것 | 쉬운 설명 | 주의할 점 |
|---|---|---|
| 파일 모양 | 같은 열 이름·빈 줄·잘린 셀을 먼저 검사 | 쉼표가 따옴표 안에 있으면 정상일 수 있음 |
| 가능한 숫자 | 인구·역 개수는 정수, 거리는 음수 불가 | 시설 0개·거리 0은 정상일 수 있음 |
| 음수의 의미 | 금리·변화율·지하 상대층은 음수도 가능 | 모든 음수를 같은 오류로 처리하지 않음 |
| 준비물 검사 | 모델을 배우기 전에 입력만 확인 | 통과해도 실험 완료나 논문 성과가 아님 |

## LEVEL 2 - Explorer

### 파일·관측·판정의 경계

원문 CSV 구조 → ID와 수치 → 특징 관측의 기간/원천 → 같은 조건의 서울 비교 → 가설 효과·구간 → 화면 근거 검사로 연결된다. 파일 행 수, 특징 관측 수, 계약 수와 단지 군집 수는 서로 다른 분모다.

변화율과 금리는 음수가 정상일 수 있고 지하층 비율도 음수다. 이 값은 보존하면서 거리·인구·시설 개수의 불가능한 값을 거부한다. 현재 자료 통과와 과거 이용가능성은 같은 뜻이 아니다.

| 흐름 | 연결하는 근거 | 구분할 분모·상태 |
|---|---|---|
| CSV → 관측 | 원문 구조·ID·수치·특징 종류 | 파일 행 수와 계약 수는 다름 |
| 관측 → 결합 | 원천·유효기간·시간대 있는 공표시점 | 현재 통과와 과거 이용 가능성은 다름 |
| 서울 비교 → 가설 | 전체 서울 집합과 고정 방법 | 군집 칼럼 누락과 군집 값 미상을 구분 |
| 가설 → 화면 | 과학 조건·반복·군집 근거 | 효과가 있어도 근거 부족이면 확정하지 않음 |

## LEVEL 3 - Practitioner

### 사전 검사 실행과 실패 해석

Python3.12와 고정 requirements.txt/requirements_acquire.txt 환경에서 python -B -X utf8 -m rentlab.feature_preflight --features features.json --output new_preflight.json을 실행한다. 기존 파일은 덮어쓰지 않고 sklearn/engine을 불러오거나 학습하지 않는다.

종료0은 validated_input_only, 종료2는 미제공/부적합 입력 또는 보고서 저장 실패다. JSON의 status·errors·manifest/관측/코드 SHA와 특징별 분모를 확인한다. 학습 재개 명령으로 해석하지 않는다. 실제 특징 미제공 검사도 종료2였으며 논문 실측은 없다.

| 실행·출력 | 확인 | 다음 행동 |
|---|---|---|
| feature_preflight | 새 출력 파일·기존 부모 폴더 | 기존 파일 덮어쓰기 금지 |
| validated_input_only / 종료 0 | 특징 입력 계약만 통과 | 계약 조인·실험 전체 준비는 별도 |
| missing_input·invalid_input / 종료 2 | 미제공 또는 부적합 근거 | 원문을 보존하고 보고서 오류를 확인 |
| 보고서 | 해시·특징별 관측/개체/원천 수·값/기간 범위 | 관측 수를 계약 수나 성능으로 해석하지 않음 |

## LEVEL 4 - Advanced

### 공통 계약과 영향 범위

input_contracts의 strict_csv는 논리 행 구조를 먼저 확인한 뒤 동일 바이트를 읽는다. 원행 리스트 전체를 복제하지 않고 ID 앞자리0을 보존한다. feature_store는 manifest와 join 양쪽에서 validate_observations를 공유하고, experiment_runner와 research_metrics는 holdout 고정 설정 검증을 공유한다.

research_protocol은 기존 고정 과학 조건을 판정하며 변경 설정을 기술 partial로 남긴다. run_dashboard는 measured 표시 전에 config·요청/유효 bootstrap·군집 근거를 확인한다. feature_preflight는 검사 보고서만 저장하고 모델 실행 모듈과 분리했다.

| 구성요소 | 현재 계약 | 거부·보존 경계 |
|---|---|---|
| strict_csv | 구조/NUL 검사 뒤 동일 바이트 파싱 | 문자 ID·앞자리 0·따옴표 안 쉼표/줄바꿈 보존 |
| validate_observations | 전체 8칼럼·정의역·유효기간·공표시점·중복 | manifest와 실제 결합이 같은 검사 사용 |
| validate_holdout_settings | 목표·라이브러리 버전·고정 추정기 인자 | 선택 모델·학습 반복수는 결과라 달라도 허용 |
| feature_preflight | 모델 import/fit 없는 보고서 생성 | 실험 readiness·과거 진실성 자동 승인 없음 |

## LEVEL 5 - Expert

### 논문 해석과 재현 조건

H1–H8와 15가족, 예측 alpha=.1/가설 family confidence=.95, seed 20261126 및 최소 군집/지역 조건을 보존한다. B≥9999, ceil(.8B)≤B_valid≤B, k≥20은 확정 상태의 필수 근거다. 설정이 달라지면 효과가 있어도 기술 partial/inconclusive다.

H5는 같은 스냅숏·전체 서울 계약과 고정 라이브러리/추정기 인자를 비교한다. 선택된 모델·학습 반복수는 결과라 달라질 수 있다. CI가 estimate를 포함한다는 조건은 넣지 않았고 군집 percentile 근사의 한계를 유지한다. 새 유의성·가설·모델 성능을 주장하지 않는다.

| 확정 조건 | 고정값·근거 | 해석 제한 |
|---|---|---|
| 과학 설정 | H1–H8·15가족·alpha=.1·confidence=.95·seed 20261126 | 변경 설정은 기술 partial/inconclusive |
| 재표집 | B≥9,999, ceil(.8B)≤B_valid≤B, k≥20 | 반복을 늘려도 요청수/config 일치 필요 |
| H6 하위집단 | low/high 각각 최소 20단지, 전체 군집 이하 | 두 하위 군집 수 합은 전체 계약 수 이하 |
| 판정 방향 | H3 동등성 범위 (-.02,.02), 방향 가설 CI 하한>0/상한≤0 | 합성 지지 억제·percentile CI 점추정 포함 강제 없음 |

| 범위 | 기존 위험 | 7차 처리 |
|---|---|---|
| CSV 입구 | 중복 머리글·빈 행·행 폭/NUL 오류를 일부 허용 | NUL/원문 구조를 먼저 검사하고 동일 바이트를 파싱 |
| 특징 값 | 유한한 숫자면 음수 개수·소수 시설도 통과 | 정의역·정수 개수·기존 단위 계약 검사 |
| 특징 manifest | feature/source 목록만으로 좁은 스키마 통과 | 전체 관측 칼럼·유효기간·공표시점·중복 ID 검사 |
| H5 재분석 | 직접 writer에서는 고정 버전·인자 비교 누락 | runner와 writer가 공통 설정 검증 사용 |
| 군집 근거 | 저장 예측 cluster 칼럼 누락을 암묵적 강등 | 필수 칼럼으로 검사; 값 미상은 불확실성 미산출 유지 |
| 분석 설정 | 소수 반복수·NaN 군집 수 등이 생성됨 | 개수·시드 타입과 범위 검사 |
| 확정 판정 | 변경된 과학 설정/부족한 재표집 근거를 확정으로 표시 가능 | 고정 조건·반복수·군집 수·유효 반복 근거 검사 |
| 사전 검사 | 외부 특징 기술 검증을 별도로 확인하기 어려움 | 모델 import/fit 없는 CLI와 새 파일 보고서 추가 |
