### 공통 계약과 영향 범위

input_contracts의 strict_csv는 논리 행 구조를 먼저 확인한 뒤 동일 바이트를 읽는다. 원행 리스트 전체를 복제하지 않고 ID 앞자리0을 보존한다. feature_store는 manifest와 join 양쪽에서 validate_observations를 공유하고, experiment_runner와 research_metrics는 holdout 고정 설정 검증을 공유한다.

research_protocol은 기존 고정 과학 조건을 판정하며 변경 설정을 기술 partial로 남긴다. run_dashboard는 measured 표시 전에 config·요청/유효 bootstrap·군집 근거를 확인한다. feature_preflight는 검사 보고서만 저장하고 모델 실행 모듈과 분리했다.

| 구성요소 | 현재 계약 | 거부·보존 경계 |
|---|---|---|
| strict_csv | 구조/NUL 검사 뒤 동일 바이트 파싱 | 문자 ID·앞자리 0·따옴표 안 쉼표/줄바꿈 보존 |
| validate_observations | 전체 8칼럼·정의역·유효기간·공표시점·중복 | manifest와 실제 결합이 같은 검사 사용 |
| validate_holdout_settings | 목표·라이브러리 버전·고정 추정기 인자 | 선택 모델·학습 반복수는 결과라 달라도 허용 |
| feature_preflight | 모델 import/fit 없는 보고서 생성 | 실험 readiness·과거 진실성 자동 승인 없음 |
