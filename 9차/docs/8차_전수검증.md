# 8차 전수 검증과 연구 조건의 경계

8차는 코드 검사와 게시를 연구 전체 완료로 잘못 묶지 않기 위해 실제 입력을 전수 대조했다. 그 과정에서 실제 실행기가 구형 입력만 선택하는 문제를 수정했다. 기존 학습 중지, 8개 가설·15개 평가, 수식·통계 문턱·분할·모델과 포함 규칙을 바꾸지 않았다. 실제 모델 적합·예측·새 가설 지지를 만들지 않았다.

## 원문 계보와 포함 규칙

48개월 원문을 인코딩에 맞게 읽고 확장 입력과 행 순서대로 21개 원문 값을 모두 대조했다. 원문 SHA와 논리 행 번호의 source_row_id, 시군구·번지·단지명에서 만든 cluster_id도 모든 행에 대해 재계산했다. 원문·확장 입력의 SHA를 처리 전후 확인했다. 각 월의 원문/입력 행 수, 스키마, 원행 식별자는 일치했다. 검사 스크립트와 민감한 행 단위 근거는 로컬 비공개로 보존한다.

기존 engine.prepare를 월별 청크로 실행해 2,857,449행과 원래 제외 사유를 확인했다. 실제 Rust 금액 파서를 썼지만 ai_candidates는 호출 시 예외가 나도록 막았고 모델을 적합하지 않았다. 검사 시간은164.684초다. 원문이 보존돼도 공개시점·소급수정의 과거 판본이 복원되는 것은 아니다.

원문 전체에서 번지 미상은31행, 도로명 미상은1,977행이고 층·건축년도 문자열 공란은0행이었다. 문자열이 채워진 것과 건축연도가 유효한 것은 다르므로 기존 건축연도 제외22,831행을 유지한다. 원문21항목에 해제사유발생일은 없다. 따라서 취소 여부를 전수 확인했거나 취소된 계약이0건이라고 주장할 수 없다. 기존 준비 과정의 취소 관측 미제공 상태를 보존한다.

## 실제 실행 입력 선택 수리

기존 실제 실험/1차의 전처리 표는 9개 학습 항목만 있고 source_row_id·cluster_id는 없었다. 현재 취득 코드가 ID를 출력한다는 사실로 이미 보관된 구형 표에도 ID가 있다고 가정할 수 없다. 실제 실행기는 root/자료_manifest.json만 읽어, 검증한 23열 확장 입력을 선택할 수 없었다. 기존 9열4,845,086행도 확장 입력에서 같은 9개 항목을 투영한 값과 모든 행이 일치했다. 다만 ID 칼럼 부재는 값 일치로 해소되지 않으며 구형 입력으로 재개하면 군집 추론 전체가 미상 처리될 수 있다. 원본·구형 표를 덮어쓰지 않았다.

experiment_runner에 --manifest를 추가했다. 생략하면 기존 root/자료_manifest.json을 유지하고, 지정하면 해당 명세를 일반·서울 홀드아웃·통합 분석에 동일하게 전달한다. 계획 JSON과 실행 상태에는 선택한 절대 경로를, 실행 상태에는 해당 SHA를 남긴다. 명시한 파일이 없으면 구형 입력으로 되돌리지 않고 실패한다. 일반 단일 실행도 입력 manifest·엔진 코드가 바뀌면 완료로 표시하지 않는다. 기존에는 이 완료 전 확인이 홀드아웃 경로에만 있었다.

```powershell
python -B -X utf8 -m rentlab.experiment_runner --root COLLECTION_ROOT --manifest EXPANDED_MANIFEST --run-dir NEW_RUN --with-holdout 서울특별시
```

위 명령은 --execute가 없는 읽기 전용 계획이다. 실제로 검증한 확장 manifest를 지정한 계획을 생성했고 학습·출력 폴더 생성·중지 상태 변경이 없음을 확인했다. 선택 옵션은 특징 승인이나 과거 라벨 승인, 사용자 중지 해제 권한이 아니다. 실제 학습은 실행하지 않았다.

5개 새 제어 검사는 입력 선택 계획의 무쓰기, 일반/홀드아웃/통합의 동일 경로, 누락된 명시 입력의 실패, 일반 실행 후 manifest 변경의 홀드아웃 차단 및 단일 실행 완료 차단을 검증한다. 실제 fit 대신 제어 콜백을 썼다. 새 옵션 부재의 RED 4개와 단일 실행 변경의 RED 1개를 관측한 후 수리했다. 최종 통합166개 검사가 통과했다.

## 군집 미상과 보정 집중

군집 미상31행의 분포는 학습8, 검증15, 보정4, 테스트4다. 번지·단지 키가 없다고 행마다 가짜 단지 ID를 부여하거나 서로 독립으로 취급하지 않았다. 현재 연구 계산은 필요한 군집이 빠지면 CI/확정 판정을 미산출·partial로 남긴다. 테스트 월세1/전세3행이 포함되므로 전체 계약에 대해 단지 bootstrap CI가 완비됐다고 보고할 수 없다. 이 결손은 입력 감사에서 발견한 연구 제약이며 프로그램이 유효한 CI를 만들었다는 관측이 아니다. 독립 식별 근거 없는 자동 보완·사후 삭제는 하지 않았다.

| 목표 | 보정 지역 | 100행 이상 지역 | 그중5단지 미만 | 최대 단일단지 비중 |
|---|---|---|---|---|
| monthly | 3017 | 537 | 20 | 100% |
| jeonse | 2708 | 605 | 29 | 100% |

지역은 원 계약의 시군구 문자열 단위다. 100행 자격은 기존 지역 보정 규칙이며 독립성 보증이 아니다. 가장 집중된 적격 지역의 계약은 한 단지에100% 몰려 있다. 5단지 미만 수는 진단용이며 새로운 보정 배제 문턱을 적용하지 않았다. H7의 지역 포함률 개선을 측정해도 단지·지역·시간 의존성과 선택 편향을 함께 해석해야 한다.

2025 테스트의 월세330,883/377,571행, 전세329,867/372,671행은 학습에 나타난 단지 군집에 속한다. 따라서 시간 이동 평가를 미학습 단지 일반화 실험이라고 부르지 않는다. H5의 서울 지역 홀드아웃과도 다른 분모다. 최대 단지 비중이나 단지 수를 유효 표본 크기로 환산하지 않았다.

## 외부 자료의 상태 정정

외부 data_path로 선언된 CSV14개를 전부 다시 읽었다. 합계427,418행은6개년 인구·시설·단지·좌표 검증표를 합한 수로 중복 판본이 포함되어 있고, 서로 다른 시설·계약427,418개를 뜻하지 않는다. manifest의 행수·SHA와 논리 행 폭/NUL을 확인했다. 원응답·다운로드 파일의 전체 재취득을 수행했다고 확대하지 않는다.

기존 국내자료 출처 목록은 이미 확보한 학교·공원·철도·인구를 미취득 후보로 남겨 두었다. 8차 목록은 실제 보유 상태·격리·후보·과거 미입증을 구분한다. KAPT API/포털 파일 후보와 실제KAPT사이트 Excel을 혼동하지 않도록 실제 취득 경로를 별도 기록했다. ECOS의 대출금리·CPI를 취득했다고 표시하지 않는다. [상태 목록](국내자료_출처목록.json).

한국부동산원 단지식별 표307,834행은 단지고유번호도307,834개다. 종류1(아파트)46,385, 종류2(연립)23,941, 종류3(다세대)237,508행이다. 따라서 전체 행 수와 광고44,628의 차이를 단순 필지 중복으로 설명할 수 없고 아파트만 골라도46,385≠44,628이다. 원래 격리를 유지한다. 공식 [명세](https://www.data.go.kr/data/15106861/fileData.do)는 여러 주택 유형·기준시점 차이와 이름 공란을 설명하지만 광고 건수 불일치를 해결하지 않는다. 이 표를 독립 연결 정답으로 승격하지 않았다.

KAPT 이름·지번·도로명과 KAPT지도는 같은 출처 체계다. 서로 일치해도 독립 정답 정확도는 아니다. 전수 진단에서 연결 계약385,030행 모두 보유 지도에서 valid_current_map_point였다. 이는 현장 좌표·측량점·출입구·보행거리를 검증한 수치가 아니다. 분모와 미연결 선택 편향을 유지한다.

## 동결과 남은 실행 경계

[연구 조건 기록](연구조건_동결.json)은 코드·입력manifest·감사보고서 해시, 고정 분할/포함 규칙과 승인하지 않은 항목을 고정한다. 이 문서는 학습 입력 features.json이나 실행 승인서가 아니다. 외부 특징이 검증됐다고 서명하거나 후보를 실제 입력에 자동 주입하지 않는다.

## 통합 분석 후 완료 경계 수리

일반·홀드아웃 실행 직후의 확인만으로는 통합 분석 writer가 실행되는 동안 바뀐 파일을 잡지 못했습니다. **통합 분석 반환 후, completed 상태를 기록하기 전에 manifest와 엔진의 SHA를 시작 시점 값과 다시 대조**합니다. 다르면 failed·종료 2이며, 실패한 분석 산출물을 성공 결과로 승인하지 않습니다. 부분 산출물은 삭제하거나 원본 결과로 덮어쓰지 않습니다.

제어 콜백이 통합 단계에서 manifest 또는 임시 엔진 파일을 바꾸는 회귀 2개는 수정 전 잘못된 종료 0을 재현했고, 수정 후 failed·종료 2를 확인했습니다. 실제 엔진·자료·기존 사용자 중지 기록은 바꾸지 않습니다. 기존 166개와 새 회귀 2개를 합친 **168개 테스트**는 프로젝트 환경에서 통과했습니다. 이는 제어 자료의 기술 검사이며 실제 학습·성능 산출이 아닙니다.

최초 [연구 조건 기록](연구조건_동결.json)은 당시 코드 해시를 그대로 보존합니다. 이후 runner 수리와 새 회귀 파일의 해시는 [완료 경계 수리 기록](완료경계_수리.json)으로 구분합니다. 입력·감사 해시, 8가설·15평가, 분할·포함 규칙과 학습 중지 조건은 변경하지 않았습니다.
