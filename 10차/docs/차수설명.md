## LEVEL 1 - Beginner

### 서로 다른 단지의 값을 지키기

표의 왼쪽 행 번호가 같아도 같은 단지는 아니다. 서로 다른 두 단지의 주변 역 수가 마지막 값으로 덮어써지는 문제를 고쳤다. 기존 정보가 있는 칸은 새 특징으로 덮어쓰지 않는다.

| 상황 | 판단 | 동작 |
|---|---|---|
| 행 번호는 같고 단지가 다름 | 각각 다른 관측 | 단지별 값을 따로 계산 |
| 기존 정보가 있는 열 | 보존할 원본 | 새 결합을 거부 |
| 모르는 단지 키 | 근거 부족 | 가짜 번호 없이 결측 유지 |

## LEVEL 2 - Explorer

### 원행·단지 키·특징을 구분하기

원행ID는 계약을, 단지ID는 위치를 가리키며 표 인덱스는 행 표식이다. 01과1처럼 다른 문자열 식별자를 구분한다. 숫자1을 문자열1로 자동 바꿔 연결하지 않는다.

| 자료 | 확인 항목 | 결과 |
|---|---|---|
| 계약→관측 | 문자열 결합키 | 정확한 키만 연결 |
| 단지→공간연산 | 고유 cluster_id와 좌표 | 인덱스 중복과 분리 |
| 특징→출력 | 값·출처·결측 열 | 기존 열과 충돌하면 중단 |

## LEVEL 4 - Advanced

### 모듈의 행 위치와 출력 계약

station_features는 내부 reset_index 후 원 인덱스를 복원한다. validate_observations와 join_features는 식별자 타입을 검사한다. join_features는 현재 관측의 생성 열 집합을 계산한 뒤 충돌을 차단한다. 원본 표와 ID를 제자리 수정하지 않는다.

| 모듈 | 경계 처리 | 보존 조건 |
|---|---|---|
| station_features | 위치 인덱스로 대입 | 원 인덱스·순서 복원 |
| feature_store | 문자열 ID 검증 | 강제 변환·키 병합 없음 |
| join_features | feature/+__record/+__missing | 충돌 시 대입 전 실패 |

## LEVEL 5 - Expert

### 수치 검증과 위치 정답의 차이

BallTree 결과를 별도의 haversine atan2 산술과 대조했다. 이는 같은 좌표로 계산한 수치 일관성을 확인하며 실제 좌표 정확도·시설 운영 이력·모집단 완전성을 증명하지 않는다. 결측 식별자와 역사판 제한은 통계 추론에서 그대로 유지한다.

| 증거 | 확인한 범위 | 확인하지 못한 범위 |
|---|---|---|
| 직접 거리 산술 | 최대차<1.924×10⁻⁹m | 현장 측량 정확도 |
| 개수/환승 대조 | 제어 물리역25개/노선30행 | 전국 시설 완전성·보행거리 |
| 178개 회귀 | 기술 조건·이전 동작 보존 | 실측 성능·가설 지지·오류부재 절대보장 |
