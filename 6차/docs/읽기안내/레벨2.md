### 자료와 판정의 연결

저장 예측 → ID·분할·모드 확인 → 같은 서울 계약 비교 → 가설 수치 → 화면 정합 확인 순서로 처리한다. 시설은 원문 행 → 중복·날짜·좌표 검사 → 재계산 가능한 보고서 → 특징 manifest로 이어진다.

한 행에 여러 보류 사유가 붙어도 원문 한 행은 그대로 보존된다. 일부 공원이 통과했다고 전국 공원 목록이 완전하다고 말할 수 없다. 현재 학교 목록이 통과해도 과거 학교 위치를 알게 된 것은 아니다.

| 처리 흐름 | 이어지는 자료 | 불일치 처리 |
|---|---|---|
| 예측 파일 → 계산 | 계약 ID·자료 모드·목표·날짜·분할 건수 | 중복·누락·알 수 없는 모드는 거부 |
| 서울 비교 → 가설 | 동일 스냅숏의 전체 서울 테스트 계약 | 일부 서울·다른 도시·보정 서울 유입 거부 |
| 요약 → 화면 | 지역 건수와 가중 평균·오차·구간 | 모순된 집계나 판정을 그대로 표시하지 않음 |
| 시설 원행 → 특징 | 원천 해시·보고서·검사 날짜 정책 | 일부 행 통과를 전체 목록 승인으로 확대하지 않음 |
